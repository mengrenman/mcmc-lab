HMC and Gibbs sampling

Random-walk Metropolis struggles when variables are strongly correlated. There are two classic cures. Hamiltonian Monte Carlo borrows the physics of a rolling particle to make long, well-aimed jumps. Gibbs sampling updates one variable at a time from its exact conditional distribution.

Hamiltonian Monte Carlo, one trajectory at a time

Treat U(x) = −log p(x) as a landscape and the current sample as a particle on it. Give the particle a random momentum p ~ N(0, 1), let it slide for L leapfrog steps of size ε, and propose the point where it stops. Along the true motion the energy H = U(x) + ½|p|² would stay constant. The leapfrog integrator keeps it only approximately constant, so the endpoint is accepted with probability

Paccept = min(1, e−ΔH)

Leapfrog is time-reversible and preserves phase-space volume. Those two properties are what make this simple rule satisfy detailed balance (book §5.1.3).

Up to 5 steps per second, each trajectory is drawn as it unfolds. Changing ε or L keeps the chain but changes how the next trajectories are integrated.

Try this

  1. Press One step several times. Each trajectory curves along the ridge of the density rather than stumbling across it.
  2. With ρ = 0.9, raise ε slowly. Past ε ≈ 0.63 the leapfrog integration becomes unstable, H explodes, and every proposal is rejected.
  3. Set L = 1. HMC becomes a small, gradient-guided random walk (Langevin dynamics). Then try L = 100 and watch trajectories loop back on themselves, which wastes work.
  4. Switch to the banana. A step size that is fine in the wide part of the ridge fails in the narrow, curved arms.

Where the 0.63 comes from

For a Gaussian, the steepest direction behaves like a spring with frequency ω = 1/√(1 − ρ). Leapfrog tracks a spring only if εω < 2, which gives ε < 2√(1 − ρ) ≈ 0.63 at ρ = 0.9. The stiffest direction limits the step size. The long, flat direction then needs many steps to cross, and that is the price HMC pays for strong correlations.

A race: Metropolis vs Gibbs vs HMC

Three chains start at the same end of the target's ridge and run the same number of iterations. To mix, each has to travel the length of the ridge and back. The effective sample size (ESS) of x measures how much independent information each chain has collected. One iteration costs very different amounts of work in each column, so ESS is also reported per unit of work.

Any change restarts all three chains, so they always compare equal settings over equal numbers of iterations.

          What to notice

          • Gibbs moves only parallel to the axes, taking steps about √(1 − ρ²) long. At ρ = 0.95 that is 0.31, so it zigzags slowly along the diagonal even though every draw is accepted.
          • Metropolis needs c small enough for the narrow direction, which leaves it a slow random walk along the long one.
          • HMC covers the diagonal in one trajectory. Each of those iterations costs L + 1 gradient evaluations, so compare the "per 1,000 evaluations" rows too.

          Try this

          1. Set ρ = 0 and run. All three do well. Gibbs is now perfect, since each draw is independent.
          2. Push ρ to 0.99 and compare how ESS per 1,000 iterations drops for each sampler.
          3. On the banana, tune c and ε by hand. Can Metropolis ever keep up?
