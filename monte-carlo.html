Monte Carlo integration

Before any Markov chains: estimate an integral by averaging over random points. The error shrinks like \(1/\sqrt{N}\) in any number of dimensions. Where you sample matters as much as how many samples you take.

Estimating \(\pi\) with random darts

Throw \(N\) points uniformly into the unit square. The fraction that lands inside the quarter circle \(x^2 + y^2 < 1\) estimates its area, \(\pi/4\), so

\[\pi \approx 4 \times \frac{\text{hits}}{N}\]

Each dart lands inside with probability \(\pi/4\), so the standard error of this estimate is \(\sqrt{\pi(4-\pi)/N} \approx 1.64/\sqrt{N}\). Quadrupling the number of darts halves the error.

Why bother, when a grid would do?

In one or two dimensions a grid is better. But a grid with \(k\) points per axis needs \(k^n\) points in \(n\) dimensions, which is the curse of dimensionality. The Monte Carlo error is \(\sigma/\sqrt{N}\) whatever \(n\) is.

The catch is \(\sigma\), the spread of the quantity being averaged. When the integrand lives in a tiny corner of the domain, \(\sigma\) is huge. The next lab shows this.

Importance sampling: sample where the integrand lives

To estimate \(I = \int f(x)\,dx\), draw \(x\) from any density \(q\) and average the weights \(w = f(x)/q(x)\). Their expectation is exactly \(I\), and

\[\operatorname{Var}(\text{estimate}) = \frac{\operatorname{Var}_q(w)}{N}\]

so a \(q\) shaped like \(|f|\) makes the weights nearly constant and the error small. Here \(f(x) = x^2 e^{-x^2/2}\), with exact integral \(\sqrt{2\pi} \approx 2.5066\). The uniform method spreads samples over the whole box \([-20, 20]\). The Gaussian proposal \(q = \mathcal{N}(0, s^2)\) keeps them in the region \(|x| \lesssim 4\) where \(f\) is not negligible. It is not a perfect match: \(q\) peaks at 0, where \(f\) vanishes. That mismatch is why the weights still vary.

Both methods take the same number of samples, each from its own random stream. Changing \(s\) starts both over.

Try this

  1. With \(s = 1.5\), run to \(N = 1{,}000\) and compare the error bars. The uniform one is about four times wider.
  2. Set \(s = 4\). The proposal is too wide, so it wastes samples, but the estimate stays well behaved.
  3. Set \(s = 0.5\) and run for a while. For long stretches the estimate looks fine, and its error bar looks small. Then a rare sample far out in the tails arrives with an enormous weight and the estimate jumps.

Too narrow is worse than too wide

For this \(f\), the variance of the weights is finite only when \(s > 1/\sqrt{2} \approx 0.71\). Below that, the proposal's tails fall off faster than \(f\), so rare tail samples carry unbounded weight. The estimate is still unbiased, but its error bar is meaningless.

In high dimensions, finding a good \(q\) is as hard as the original problem. MCMC gets around this by drawing from \(p\) itself, without ever knowing its normalization.
